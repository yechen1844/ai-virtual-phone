# 星露谷 + 主聊天 · PC↔手机实时同步 计划书

> 目标：玩星露谷时，手动打开「实时同步」，电脑端与手机端 float 实时互通**星露谷会话 + 主聊天**的**消息 / 记忆 / 设置**；char 的工具调用只在「游玩端」执行。避免全量备份的慢速与资源浪费，做到增量、不丢、可控。

***

## 一、设计原则

1. **手动开关、两端同开**：同步只在用户手动打开时进行，且**两端必须都打开**才真实拉取/写入，关掉即零资源消耗。
2. **方案 A**：复用微信回收的同款「云文件 + 短轮询」结构（消息落成云 JSON 增量文件，靠 `CHAT_MESSAGE_PUSHED_EVENT` + `setInterval` 短轮询拉取），在对称的电脑端/手机端 float 各跑一份。
3. **游玩端指定**：一个「游玩端」开关，让用户选哪台是 PC 游玩端。**只有游玩端执行 char 的工具调用**；另一端（手机）只做「收发消息 + 显示」，收到工具态也只当普通消息呈现，绝不执行工具。
4. **尽量复用**：复用 `lib/cloud-backup/storage-client`（anon key + REST + 超时重试）、`lib/weixin-cloud-sync` 的云文件/增量/去重思路；不新引入 supabase-js。

***

## 二、同步范围（按你的要求：消息 / 记忆 / 设置）

按会话隔离到一个专属前缀，例如 `sync/` 桶内独立目录，与现有备份 `modules/`、`media/` 分开，互不干扰。

| 数据                                  | 说明                        |
| ----------------------------------- | ------------------------- |
| 星露谷会话消息 `sess_stardew_*`            | 双向增量同步                    |
| 主聊天会话消息（非群）                         | 双向增量同步                    |
| 记忆（`recent_stardew` 投影 / 相关记忆条目）    | 跟随消息同步，保证两端一致             |
| 设置（同步所需的 Bindings/Preset/关联 API 配置） | 同步一次（避免手机端找不到 preset/API） |

***

## 三、消息流（核心）

```
[电脑端 float]                            [手机端 float]
  用户发消息/char回复                       用户发消息/char回复(仅文本,不调工具)
       │  → 写云 sync/<会话>/<msgId>.json        │  → 写云 sync/<会话>/<msgId>.json
       │                                       │
       ◀──────── 短轮询 Pull 云端新增 ─────────  │
     拉回手机发的消息 → upsert 进本地          拉回电脑发的消息 → upsert 进本地
ChatMessage 事件/轮询驱动重新组装 → char 回复
```

- **工具调用只在游玩端**：`generateChatCompletion` 的 `forceEnableTools` 只在游玩端为 true；手机端关掉工具（`forceEnableTools=false`），只发文本。

- **去重 & 防丢**：写入带全局唯一 `msgId`；拉取用 `upsertImportedChatMessage`（按 id 幂等合并）；记 `lastSyncedAt`/缓存的已同步 id 水位，只拉新增。

- **冲突**（两端同一会话同时写）：按 `createdAt` + `msgId` 排序取新者，旧者不覆盖；异常时保留两端、不做破坏性删除。

***

## 四、游玩端判定（关键）

新增设置项 `syncPlaybackDevice: "pc" | "mobile"`（一个切换按钮，两侧各自显示当前自己是不是游玩端）。

- **游玩端（PC）**：`forceEnableTools=true`，char 正常调工具。

- **手机端**：`forceEnableTools=false`，纯文本对话。即便模型偶然想调工具，也走 `forceEnableTools=false` 分支，不执行（可视需求加「工具调用转为文本提示」的降级）。

> 每次打开同步时，把两端的 `syncPlaybackDevice` 广播给对方，供界面展示「当前游玩端：电脑/手机」。

***

## 五、手动开关行为

- 一个「实时同步」总开关 + 一个「游玩端」开关（可合并到同一设置面板）。

- **开启**：启动短轮询（默认 3\~5 秒，可在设置里调）+ 开始监听本地 `CHAT_MESSAGE_PUSHED_EVENT`，有新增就立即写云。

- **关闭**：停止轮询与推送、清除定时器；已下载数据保留在本地为只读。**两端都关 = 零云请求**。

- 断网/报错：静默重试 + 有限次内的 `show_notice` 提示，不阻塞聊天。

## 六、令牌获取（最后只给你必要项自己填）

你创建 Supabase 项目后，给我/或自己填以下 3 个值（计划书实现时只读这几项）：

1. **Project URL**（`https://xxxx.supabase.co`）—— 设置页「项目地址」。
2. **anon / public key** —— `Project Settings → API → anon public`。**浏览器端只用 anon**（沿用现有 storage-client），权限由「桶策略」限定在 `sync/` 前缀，**不必给我 service\_role**。
3. （如需自动建桶/建策略）**service\_role key** —— 仅由「一键初始化」步骤在受控时刻使用，普通同步不碰。

> 安全要点：浏览器分发**只带 anon key**；service\_role 只用于一次性建桶/写 RLS 策略；`sync/` 桶策略限制为「读写本用户的前缀」，避免跨设备互覆盖他端。

## 七、实施步骤（计划，待拍板后逐条做）

1. **配置层**：新增同步配置（开关 / 游玩端 / 轮询间隔 / 已同步水位），存 kv。
2. **云文件读写**：封装 `sync/` 前缀下的消息 JSON 读写（增量 list + upsert），复用 storage-client 的 fetch/超时/重试。
3. **游玩端开关**：`syncPlaybackDevice` 广播 + 界面切换按钮 + `forceEnableTools` 按端分支。
4. **消息同步引擎**：写云（本地新增）+ 拉云（短轮询 + 事件）+ 幂等合并 + 去重水位。
5. **记忆/设置跟随**：同步 `recent_stardew` 投影与必要设置。
6. **错误与防丢**：超时/断流重试、异常不破坏、冲突按时间取新。
7. **UI**：设置面板（开关/游玩端/间隔）+ 同步状态指示。
8. **测试**：两端开同步 → 收发、工具只在游玩端执行、关掉后零请求。

## 八、边界（暂时不做）

- 真正的 websocket 服务器推送（先短轮询够用）。

- 全量媒体/大文件实时同步（沿用云备份离线场景）。

- 多端 > 2 的复杂冲突合并。
