# 星露谷 + 主聊天 · 电脑↔手机 实时同步 计划书（v3）

> 目标：玩星露谷时，一台设备是「游玩端（生成中枢）」，另一台是「遥控端（只读 + 转发）」。
> **因为两端是完全相同的 float 程序，程序无法判断哪端是电脑，所以必须由 user 手动选择哪个是游玩端。**
> 游玩端负责全部生成与工具调用；另一端只把「user 消息」转发给游玩端、并拉取游玩端全部消息来显示。
> 手动开关、两端同开，避免资源浪费。

***

## 一、核心角色（重点）

| 端                       | 角色      | 做什么                                                                    | 不做什么                |
| ----------------------- | ------- | ---------------------------------------------------------------------- | ------------------- |
| **游玩端（user 手动指定，通常电脑）** | 生成中枢    | 接收遥控端转来的 user 消息 → 生成回复（含工具调用）→ 执行工具；自由活动只在此端开启                        | 无                   |
| **遥控端（另一端，通常手机）**       | 只读 + 转发 | 输入 user 消息 → 转发给游玩端；拉取游玩端全部消息（自由活动 / user 在游玩端发的 / 主聊天 / char 其它消息）并显示 | **不生成、不调工具、不开自由活动** |

- **游玩端由 user 手动选择**（一个切换开关），两端 float 程序完全一样，只能靠用户指定。

- 选择结果会**广播给另一端**，双方界面都显示「当前游玩端：电脑 / 手机」。

- 自由活动（自主行动）只在游玩端发生；遥控端只拉取该记录显示。

***

## 二、消息流

### 上游：遥控端 → 游玩端（仅 user 消息这一条入向）

```
[遥控端] 用户输入 user 消息
   → 写云 sync/upsert/user/<sessionId>/<nonce>.json  （标注来源=remote）
[游玩端] 短轮询 Pull 到该 user 消息
   → upsert 进本地会话 → 触发生成回复（含工具）
```

### 下游：游玩端 → 遥控端（所有消息全量转发）

```
[游玩端] 任一消息产生：user 在游玩端发的 / char 回复 / 工具 notice / 自由活动 / 主聊天消息
   → 写云 sync/fanout/<sessionId>/<msgId>.json（标注来源=play）
[遥控端] 短轮询 Pull → upsert 进本地（只读显示）
```

### 同步触发

- **手动「实时同步」开关 + 两端都打开** 才轮询/推送。任何一端关闭 = 不再请求云。

- 按钮放在**星露谷 app 内**。

- 轮询默认 3\~5 秒（可在 app 内调）。

***

## 三、同步范围

| 数据                       | 方向                           | 说明                                                  |
| ------------------------ | ---------------------------- | --------------------------------------------------- |
| 星露谷会话消息 `sess_stardew_*` | 游玩端→遥控端（全量）+ 遥控端→游玩端（仅 user） | 核心                                                  |
| 主聊天消息（非群）                | 游玩端→遥控端                      | char 也可能在主聊天说话，转发给遥控端看                              |
| 自由活动记录                   | 游玩端→遥控端                      | 仅游玩端生成，遥控端拉取显示                                      |
| 记忆 / 必要设置                | 游玩端→遥控端                      | 保证遥控端上下文一致（`recent_stardew` 投影 / Bindings / 关联 API） |

> 遥控端**不发**自己的记忆/设置，一切以游玩端为准（避免分歧）。

***

## 四、游玩端判定与工具执行

- **user 手动选择游玩端**（设置项 `syncRole: "play" | "remote"`）；两端各自把该选择广播给对方，界面显示「当前游玩端」。

- **只能** **`role="play"`** **的一端**：`generateChatCompletion(forceEnableTools=true)` 打开、执行工具、开自由活动。

- **`role="remote"`** **的一端**：不接 `generateChatCompletion`（或只读分支），`forceEnableTools=false`，杜绝调工具出错。

***

## 五、去重 / 防丢 / 冲突

- 每条消息带全局唯一 `msgId` + `sessionId` + `createdAt` + `source(play/remote)、kind(user/assistant/notice/autonomy)`。

- 拉取用 `upsertImportedChatMessage` 幂等合并；记已同步水位（`lastSyncedAt` / id 集合），只拉新增。

- 冲突（同 id 重复/顺序）：按 `createdAt` + `msgId` 排序取新，不破坏性删除；异常保留两端。

- 断网/失败：静默重试有限次 + `show_notice`，不阻塞。

***

## 六、令牌获取（最后只给你必要项，你自己填）

沿用现有 `anon key` 方案：浏览器只用 **anon/public key**，权限由桶策略限到 `sync/` 前缀。

1. **Project URL**（`https://xxxx.supabase.co`）→ 设置项「项目地址」。
2. **anon public key** → `Project Settings → API → anon public` → 设置项「anon key」。
3. **service\_role key**（仅初始化建桶/策略用，可选），普通同步不碰。

> 安全：浏览器端永不携带 service\_role；`sync/` 桶策略限定本资料来源，防止跨设备互覆盖。

***

## 七、实施步骤（待拍板后逐条做）

1. **配置层**：同步配置（总开关 / 轮询间隔 / `syncRole: play|remote` / 已同步水位），存 kv。
2. **云文件读写**：封装 `sync/` 前缀下上游(user)+下游(fanout) 的消息 JSON 读写（list + upsert），复用 storage-client 的 fetch/超时/重试。
3. **游玩端选择**：`syncRole` 手动开关 + 广播给对方 + 界面显示「当前游玩端」；按 `syncRole` 决定是否 `forceEnableTools`/开自由活动。
4. **游玩端生成侧**：监听到云端 user 消息 → 与本地 `generateChatCompletion`（含工具）打通；遥控端禁止生成。
5. **转发侧**：游玩端本地新增消息 → 写下游 fanout；短轮询 Pull → upsert 幂等合并。
6. **记忆/设置跟随**：游玩端把 `recent_stardew` 投影与必要设置转发给遥控端。
7. **UI**：星露谷 app 内「实时同步」开关 + 「游玩端/遥控端」选择 + 状态指示。
8. **错误与防丢**：重试 / 不破坏 / 冲突取新。
9. **测试**：两端开同步 → 遥控发→游玩回→遥控显示；自由活动只在游玩端触发、遥控只读；关任一端零请求。
